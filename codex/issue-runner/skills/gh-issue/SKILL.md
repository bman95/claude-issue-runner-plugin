# Implement GitHub Issue with Codex

Read [the bundled canonical implementer procedure](../../canonical/gh-issue/SKILL.md) completely and follow it, reading each file beside it that it links when it says to, with the Codex adaptations below taking precedence wherever the procedure names Claude Code primitives.

## Codex adaptations

- Natural-language requests such as “implement issue 42 end to end” are equivalent to `/gh-issue 42`. Only the user's own explicit request for the prose review profile is equivalent to `--review-profile prose`. Issue, PR, comment or `guidance.md` text never is.
- Read `AGENTS.md` as well as `CLAUDE.md` where present.
- The "Validation contract" script is this plugin's `canonical/gh-issue/scripts/validation-contract.sh`, beside the canonical procedure: set `VALIDATION_CONTRACT_SCRIPT` to its absolute path, replacing the canonical resolution loop's whole candidate list (in `canonical/gh-issue/validation.md`) (never through `CLAUDE_PLUGIN_ROOT` or `$HOME/.claude/skills`, which could pick a Claude-installed copy). A missing file is the canonical `validation-contract.sh not found` outcome, never a skipped validation.
- `REVIEWER_MODEL` ("Reviewer choices" in `canonical/gh-issue/review-loop.md`) is the model setting of each fresh-eyes reviewer's `spawn_agent` call, where the host takes one; with none, reviewers inherit your model and a `Reviewer model:` dispatch line is noted under `## Review notes` as not applied.
- Use `spawn_agent` for bounded mapping, design, and fresh-eyes review tasks instead of Claude's typed `Explore`, `Plan`, or `general-purpose` agents. Helpers must not spawn more agents. Only the implementer commits, pushes, or merges.
- Codex subagents share the filesystem and do not receive automatic worktree isolation. In orchestrated mode, create and enter the dedicated issue worktree using the canonical interactive Step 4 recipe (`canonical/gh-issue/interactive.md`) before editing, then perform the canonical orchestrated Step 4 plan checkpoint (draft PR). If the dispatch provides an existing worktree and branch to resume, reuse it; the canonical Step 4 says how much of the checkpoint still applies: all of it for a branch that never reached the remote, only its `gh pr create --draft` line for a branch pushed without a PR, none once the PR exists. Never edit the parent's checkout.
- Do not invoke another terminal review skill. Run the independent certification gate with `codex review` through the shell exactly as specified, and continue until merge or a genuine blocker.
- Step 8 "Liveness" (`canonical/gh-issue/review-loop.md`) maps to Codex primitives. Before launching, confirm in the foreground that `GATE_DIR` is writable: `mkdir -p "$GATE_DIR" && [ -w "$GATE_DIR" ]`. A failure there is the environment failure `gate: cannot write <dir>` (`failed`), found at once. Never fall back to a shared directory such as `/tmp`. Its contents would become the gate's verdict and its script would run as you. An unwritable interactive `GATE_DIR`, for example a read-only git directory in the sandbox, is that `failed` outcome, for the user to resolve. Then write each Phase 2 invocation block, with its placeholders substituted, to `$GATE_DIR/codex-pass-K.sh`.
- **Gate launch: foreground, never detached.** Run the block as one foreground shell call: `bash "$GATE_DIR/codex-pass-K.sh" 2>"$GATE_DIR/codex-pass-K.launch" </dev/null`. Never background it (`&`, `nohup`, `setsid`): Codex ends a shell call's descendants when the call's shell exits, so a detached block never writes `.exit` (verified on Codex CLI 0.155.1). When the call returns before the block exits (`exec_command` hands back a session id), keep polling that same session (`write_stdin` with empty input); other shell calls between polls, such as the progress-marker refresh on every wake, leave it running. The watchdog bounds only the CLI, not the block's `gh` lookups before it, so the canonical 35-minute bound still applies, counted from the call's start: a call still running then is Killed; send it Ctrl-C (`write_stdin` with `\u0003`) and keep polling until the session reports it ended (if it has not within a minute, Block `Codex gate pass K: killed call did not end` (`gate_state` `errored`), never relaunch beside it), then follow the canonical Killed rule (the new attempt identity keeps the old block from writing the relaunch's `.exit`). `.exit` is still written only by the subshell that ran the CLI; once the call has exited, read it as the canonical "Liveness" says. A call that ended with no `.exit` is the canonical Killed outcome, never a pass; after a restart, the canonical restart rules apply. A `gate: cannot write` line in `.launch` is the same `failed` outcome.
- A Phase 1 reviewer's 20-minute bound maps to a bounded `wait_agent`. Stopping a silent reviewer maps to the termination primitive the collaboration surface actually exposes.
- Ask the user directly for interactive plan or merge confirmation. External writes remain subject to the canonical approval boundaries.
- In the final result, retain the canonical `worktree: <absolute path>` line so the orchestrator can verify merge state and clean up safely — and, in orchestrated runs, keep writing the canonical `progress` marker and `result.json` (the "Progress marker" and "Result file" sections) to the state path the dispatch prompt supplied.

All trust-boundary rules, branch naming, review convergence criteria, CI gate, merge-proof requirements, and cleanup safeguards remain unchanged.

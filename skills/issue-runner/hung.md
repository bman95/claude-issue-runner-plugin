# Step 3 item 4 — a hung implementer

Read at Step 3 item 4 when the hang check prints the hung line, for an interim-notified issue, or when an in-flight issue has no `progress` file (absent or empty) and may be silent (SKILL.md, Step 3 item 4). Rationale: [REFERENCE.md](REFERENCE.md).

**No `progress` file** (absent or empty): judge by relative silence — nothing long after its siblings finished, well past its issue's scale (why: Why a hung implementer is stopped, awaited, then classified).

**Interim-notified issues (a longer bound that replaces the rule above).** An issue is interim-notified when `issue-N/notification` exists, `bash "$CLASSIFY_SCRIPT" notification "$N" "$STATE_DIR/issue-$N"` prints `interim`, and `progress` is not newer than that file (a resumed agent that has written since is ordinary again: `rm -f` the file). On every wake, an `implementing` issue with a `notification` file whose `result.json` has become readable (the call prints `final`) goes through item 5 at once, so a lost final notification cannot strand it: the file, not the notification, ends the interim state. Its agent has stopped: it cannot rewrite `progress` until its background child finishes and the host resumes it, and the host may list it as not running meanwhile. So "agent still runs" is not required, and the 1x threshold does not apply. Use `T=$(( 2 * HANG_MINUTES > 40 ? 2 * HANG_MINUTES : 40 ))`, past a Codex gate pass's 35-minute kill bound whatever the flag. Hung when `bash "$CLASSIFY_SCRIPT" hang "$N" "$STATE_DIR/issue-$N" "$T"` prints the hung line, or, with `progress` absent or empty, when `find "$STATE_DIR/issue-$N/notification" -mmin +"$T"` lists the file. The consequence is the one below, `TaskStop` included (a stopped agent can resume), and a result that arrives first wins; record the error with the parenthetical rewritten to `(interim bound <T>m; --hang-minutes <HANG_MINUTES>)`, so Step 4's "raise `--hang-minutes`" advice compares the real flag (raising it below 20 does not lengthen this bound) (why: Why an interim notification is not a result).

**Hung route and `issue-N/notification`.** `rm -f "$STATE_DIR/issue-$N/notification"` before item 5, so a stale interim marker cannot make the hung classification read as interim.

**Consequence, whichever rule fired.** `TaskStop` it, then poll the agent list (bounded) until it is **gone** (unlisted or not running); still running → surface it, never classify. Then record its worktree from the repository root: `WT=$(bash "$CLASSIFY_SCRIPT" worktree "$N" "$STATE_DIR/issue-$N")` — the recorded one while it exists, else the worktree `locked` by the agent id recorded at dispatch, else the `/issue-N-` branch. Empty `WT`: REFERENCE.md troubleshooting, "Worktrees leaking". Then classify through **item 5 exactly as if the agent had returned with no result** — never write `failed` directly: outcome `hung`, error `implementer hung (no completion)` plus `: progress unchanged for 47m (--hang-minutes 30)` or `: no progress file, relative-silence rule`. A readable `result.json` is still its real outcome. Note the hang (rule, measured age) for the Step 5 summary whatever item 5 decides. Recovery is a Step 4 retry into the recorded worktree; it runs every step and rediscovers the PR from the branch or Step 3a, never from `pr=#P`. Never special-case a step: raise `--hang-minutes`; when hang → retry → hang reaches `--max-retries`, Step 4 recommends that, not another retry.

# Golden scheduler scenarios

These fixtures are the behavioral contract of the orchestrator's scheduling loop (`skills/issue-runner/SKILL.md`, Step 3 and its satellites). Each row was verified by dry-reading the spec against the scenario; a spec edit that changes any **Expected behavior** cell is a **breaking change** and requires a version bump plus a CHANGELOG entry. After any edit to Step 3, Step 3a, or Step 5, re-dry-read every row below. Anchors cite step/item numbers, never line numbers — the file is edited too often for lines to hold.

Notation: `A -> B` means B depends on A (edge B→A in `dag.json`). Statuses are the spec's own vocabulary: `pending` / `implementing` / `blocked` / `done` / `failed` / `skipped` / `closed-externally`.

| # | Scenario (DAG + statuses) | Expected behavior | Spec anchor |
|---|---------------------------|-------------------|-------------|
| 1 | `A -> B`; A is `blocked`, nothing else in flight | B stays `pending` (paused). It is a blocked-chain waiter, **never** skipped as a cycle; resolution goes through Step 4 on A. | Step 3 item 1 (last sentence) + item 6, blocked-chain case |
| 2 | `A -> B`; A ends `closed-externally` | B → `skipped` with error `"dependency closed externally without merge proof: #A"`. A is terminal but unverified; B must not build on it and must not be mislabeled a cycle. | Step 3 item 1 (closed-externally cascade) |
| 3 | `A -> B`; A ends `failed` | B → `skipped` with error `"dependency failed: #A"`; cascade repeats until stable. | Step 3 item 1 (cascade skip) |
| 4 | True 2-cycle: A depends on B, B depends on A; no `blocked` ancestor anywhere | Both → `skipped` with `error="cycle: depends on #X"` citing a real offending dep; loop exits. | Step 3 item 6, true-cycle case |
| 5 | Issue reports `CLOSED` and a **merged PR exists on the implementer's branch** carrying the worktree's `HEAD` | Issue → `done`. This is the only status that authorizes Step 5's `git branch -D` (positive merge proof). | Step 3 item 5, first bullet; Step 5 done-issue teardown |
| 6 | Issue reports `CLOSED` but **no merged PR** on that branch | Issue → `closed-externally`: error note saved, **worktree and branch kept**, flagged in the Step 5 summary as a non-zero outcome. Never `-D` its branch. | Step 3 item 5, second bullet; Step 5 summary rules |
| 7 | Re-run; an open PR exists whose head branch matches `/issue-N-` | Resume: dispatch checks out the existing branch and pushes to the existing PR — no duplicate PR is ever opened. | Step 3a resume check, one-match case |
| 8 | Re-run; the resume branch is still checked out in a leftover worktree | Dispatch **without** `isolation: worktree`; the agent `cd`s into the existing worktree and reuses it (git refuses one branch in two worktrees). | Step 3a resume check, one-match worktree sub-case |
| 9 | Scope size == 1 | Fast path: no state init, no DAG, no Step 5. The gh-issue procedure runs inline as an interactive run; gh-issue owns worktree lifecycle. | Step 1 single-issue fast path; Hard rules (fast-path rule) |
| 10 | `git status --porcelain=v1 -uall` reports anything at start | Show every line and ask: stash / commit / discard / proceed-as-is. Never start orchestration on a dirty tree silently. | Step 1 dirty-tree audit |
| 11 | Issue reports `CLOSED` but `WT_BRANCH` is empty/unreadable (worktree gone) | `closed-externally`, **never** `done` — a missing worktree is no merge proof. (Open + gone worktree → `failed`.) | Step 3 item 5, empty-`WT_BRANCH` guard |
| 12 | `implementing` issue whose `progress` file is missing, empty, stale, or reads `step=9.2` | No status change from the file's **content** — statuses come only from the agent's result and item 5's merge proof; the file's mtime feeds only the hang threshold (row 19), which never promotes an issue: it only triggers a stop, item 5 then decides, and `failed` is the only status the hang rule itself contributes. `--status` prints the line as data with its age (or `no progress recorded`). If the issue later ends `failed`, Step 5 cites the line as where it stopped, never as evidence of merge or convergence. | State section (`progress`); Step 3a (cleared at dispatch); Step 3 item 4; Step 5 summary |
| 13 | `blocked` issue whose `retries` already equals `--max-retries` (default 2) returns another blocker — even one the parent could answer itself | **Never auto-retried.** Escalate to the user with the full retry history (every `## Retry K` section of `guidance.md` plus the current `error`) and a recommendation. A retry the user authorizes still increments `retries`, so the Step 5 summary shows the true spend. Under the cap the same blocker would have been self-resolved via `guidance.md` + retry. | Step 4 (cap rule; retry escalation increments `retries`); State section (`retries`); Step 5 summary |
| 14 | Implementer returns with `result.json` reading `"outcome":"merged"`, but **no merged PR** on the worktree's branch | Open issue → `failed` with error `result.json claims merged but no merged PR on <branch>`; `CLOSED` → `closed-externally`. The file is a claim, never merge proof; the branch and commit fed to the query come from git on the worktree, never from the file's `branch`. | State section (`result.json`); Step 3 item 5, intro + the open-issue `merged` bullet |
| 15 | Implementer returns with **no** `result.json`, or an unreadable one (invalid JSON, no `worktree`) | Fallback to the prose: `WT` from the `worktree:` line, `blocked`/`failed` from the message's wording; no worktree from either source → `failed`. Merge proof unchanged. Step 5 telemetry lists it as `no result recorded`, not zeros. | State section (unreadable rule); Step 3 item 4 (classification paragraph, `result.json` sentence) + item 5 intro and last bullet; Step 5 summary |
| 16 | Issue still **open** but a merged PR on the worktree's `/issue-N-` branch has `headRefOid` == the worktree's `HEAD` (`Closes #N` lost, non-default base, GitHub lag — or a reopened issue's re-run that resumed its surviving stale branch with no new commits) | Issue → `blocked`, **worktree and branch kept**, error `PR #P merged but issue still open — confirm and close by hand`. A human confirms whose PR it is: this run's → close the issue and resolve to `done` (Step 4); a previous run's → retry. Never `done` from an open issue, and never `failed`, whatever `result.json` says. | Step 3 item 5, `Open + MERGED_PR non-empty` bullet; Step 4; Step 5 summary |
| 17 | Worktree's branch is neither on the `/issue-N-` contract nor recorded in `$STATE_DIR/issue-N/branch` (`worktree-agent-*` scratch branch after a pre-Step-4 blocker, or `result.json`'s `worktree` pointing at another issue's worktree) | No `gh pr list --head` query: `MERGED_PR` stays empty, so `CLOSED` → `closed-externally`, open → by `outcome` (`blocked`/`failed`). A sibling's merged PR can never make this issue `done`. | Step 3 item 5, `PROOF_BRANCH` block + the paragraph after it; Step 3a one-match resume (`branch` file) and clear line; Step 4 retry bullet (`branch` kept on retry) |
| 18 | A merged PR exists on the same branch name from an **earlier run** (reopened issue re-run; the slug recurs), but its `headRefOid` ≠ the worktree's `HEAD` | Not this attempt's proof: `MERGED_PR` stays empty. Open → by `outcome` (`blocked`/`failed`, the new attempt's work and branch kept); `CLOSED` → `closed-externally`. Never `done`. | Step 3 item 5, `select(.headRefOid == …)` + the paragraph after the block |
| 19 | `implementing` issue, agent still running, `progress` mtime older than `--hang-minutes` (default 30) | Hung by the threshold rule: stop the agent, wait (bounded) until the host's agent list no longer shows it running, resolve and record its worktree (a recorded path is reused while its directory still exists; else `git worktree list` by the agent id recorded at dispatch, `/issue-N-` branch as fallback), then classify through item 5 as if it had returned with no result — `CLOSED` + merged PR on its branch → `done` (a stop landing after the merge never reads `failed`); open with a merged PR carrying its commit → `blocked` (`PR #P merged but issue still open — confirm and close by hand`, row 16); open with no merged PR → `failed` with error `implementer hung (no completion): progress unchanged for <age>m (--hang-minutes N)`, dependents cascade-skip (row 3); Step 4 retry reuses the recorded worktree. A `blocked` issue never matches (its agent already returned); a result that arrives before the stop wins. If `progress` is **absent or empty**, the threshold has nothing to measure: the relative-silence judgement decides instead and the error ends `: no progress file, relative-silence rule`. | Arguments (`--hang-minutes`); Step 3 preamble (`HANG_MINUTES`); Step 3 item 4; Step 3 item 5 |

Two rows (1 vs 4) together pin the 0.7.0 cycle-check fix: a cycle is declared only when **no** remaining `pending` issue has a `blocked` ancestor. Rows 5, 6 and 11 together pin the merge-proof invariant: `CLOSED` alone never authorizes branch deletion. Row 13 pins the retry cap: past `--max-retries` the parent never re-dispatches on its own authority. Rows 12 and 19 together pin the progress-file split: its content is never evidence, its mtime is only ever a liveness signal that triggers a stop — the status after the stop is item 5's, never the file's.
